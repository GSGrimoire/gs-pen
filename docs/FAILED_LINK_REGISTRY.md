## Collection, retention, measurement
Budget-approved recognized user requests count starts and completed outcomes independently; success means native captions, partial means metadata/post without captions, failure means neither. Invalid/unrecognized, quota-denied and browser-only failures are excluded. User and scheduled attempts are separate populations; rate = (failed + partial) / completed. Incomplete starts are visible; storage outages may undercount both, so not an exhaustive traffic audit. Ordinary successful links are not added to research unless resolving an existing case. No transcript, URL, case or trace ID in permanent counters; owner ID solely for authorization. UTC month of request/check start. Only the maintenance heartbeat retains an exact time; ordinary counter buckets store the month boundary. Report shows latest 24 months; historical counters retained.
Normalized recognized replayable submitted links only, not verified provider identity; aliases separate. Required identifiers retained, tracking query/fragment removed. Every link is confidential, recognition does not prove public access.
Maximum generation age 180 days from earliest recorded attempt, non-sliding. Later capture after expiry creates a fresh generation. Automatic monthly rechecks of unresolved cases from earlier UTC months (one claim per case/month). Recovered cases removed after aggregate outcome commit only if version is current; unresolved retained until age cap. Ordinary user-resolved cases need no automatic recheck and expire by age. Explicit owner delete remains optional; saved Recent and aggregates unaffected. Retention affects research only, not diagnostic events, Recent or content jobs. Backups/assistant conversations have separate retention. Read paths hide expired generations; capture and scheduled paths physically delete them. Physical deletion requires healthy runtime; no guarantee during outage. 180 days is conservative for six months; shorten only by reviewed owner decision when traffic increases.
## Scheduled runtime and safety
worker/index.ts scheduled handler; Vite worker config declares */15 * * * * UTC. Tick expires old cases, writes aggregate maintenance heartbeat, selects at most one case, checks shared durable request budget (fail closed), atomically marks first row with current month before retrieval, records aggregate start, calls existing bounded public caption resolver without cookies, raw logs, transcript persistence, Recent writes or model calls, then records sanitized outcome. No HTTP or assistant scheduled-write route. Duplicate ticks cannot claim same generation/month. Lost claim/acknowledgment not blindly retried; starts without outcomes show incomplete. Crash between claim and start can skip until next month, no provider call in that gap. Stats failure before fetch blocks it; after fetch prevents deletion. Concurrent deletion after claim cannot revoke an in-flight fetch; no research record recreated. Capacity at most 96 claims/day under normal cadence, budget denial/backlog possible. Verify coverage before scale.
Assistant reads are owner-scoped and expiry-filtered without writes; get_reliability_report returns aggregate only. Confidential links are untrusted data; never forward publicly. No assistant retrieval or mutation. Existing extraction exports outside research unchanged.
