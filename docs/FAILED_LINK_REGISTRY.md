# Failed Links Registry (#61) — corrected scope after Full Review
## Behavior and scope
Owner-scoped registry of completed server-side attempts for normalized recognized replayable submitted links. Each case groups the same normalized submitted URL, NOT verified provider identity: host aliases, short/canonical routes and distinct representations remain separate. Tracking query/fragment removed; required public-format identifiers retained. Encoded or ambiguous path segments rejected. Link recognition does not prove public access; share tokens and every source link are confidential. No raw URL cache. Partial vs total failure vs native-caption resolution; later failure reopens the case. Ordinary successful extractions not recorded. Browser-only failures, malformed/unrecognized or non-replayable links, quota denial, and storage failures are excluded. Connection interruption after dispatch is unknown; refresh before retry. Storage remains optional after mandatory quota approval.
## Review correction: remote transfer removed
H1/H3/H4: a mutable GitHub visibility check is not a private-transfer invariant; the available personal repository has no verified atomic privacy guard. Therefore this candidate has **no remote GitHub client, no credential binding, no enable flag, no automatic transfer, and no remote write operation**. Legacy POST /api/failed-links/:id/export is explicitly denied even if an obsolete secret is present. No pending export or ambiguous external write can be initiated by this candidate. Owner UI offers a local file download with selected URL, attempt ID, outcome and destination confirmation; no remote transfer is claimed. Import deliberately into the verified private research repository using an authorized GitHub session, never public source, issues, logs or fixtures. No automatic live replay workflows. Existing private owner-reported seed remains unverified. Manual download/import is a scope reduction, not completion of automatic synchronization. A separately reviewed implementation must establish enforceable private repository identity/visibility, least privilege, durable write receipts and reconciliation, lifecycle and confirmation protections before credentialed export can return. Do not configure a Site token for this release.
## Lifecycle and pagination
One atomic INSERT assigns a database monotonic completion sequence and existing case generation or a fresh UUID generation. Cases sort by first sequence, not mutable latest attempt; attempts sort by descending sequence, even equal timestamps. Live keyset pages are bounded to 50; new cases/attempts above the cursor appear on refresh, deleted cases may disappear, old case IDs never refer to a replacement. Latest attempt is the completion-order outcome; no claim of request start order. Delete requires stable case ID + displayed latest sequence and one atomic conditional DELETE with actual changed rows; stale confirmation returns conflict, capture after deletion forms a new generation (including an already in-flight retrieval that completes afterward). Manual local downloads are independent copies, not external write receipts; deletion cannot revoke them, Git history, Recent or assistant conversation copies. Owner may refresh and re-confirm. Indexes cover owner/source/seq, owner/case/seq and unique attempt ID; whole-owner group aggregation remains a potential large-history performance cost, benchmark before large-scale use.
## Assistant and provider boundaries
Read-only tools list_failed_links and list_failed_link_attempts read the hosted database, NOT the external corpus. The latter takes stable case ID; cursor is a positive bounded decimal sequence. Confidential untrusted data must not be forwarded to public tools; assistant conversation retention is independent. No assistant retry/delete/export. Budget correction from #59 is integrated in this branch: no provider calls if quota storage fails, including retry; optional diagnostic/history/registry writes fail independently. #59 remains separately open and unmerged; independent review combined head, reconcile overlapping changes without reintroducing fail-open.

## Failure-mode matrix
Invalid/non-replayable URL: no registry row. Missing budget: 503/no provider call. Rate limit: 429/no registry row. Provider failure/partial: capture if eligible; successful prior case: resolved. Optional registry outage: result still returned with storage_failed. Browser timeout/response lost: unknown server completion. Stale delete: conflict and refresh. Deleted generation: no replacement access. Foreign owner or origin: denied. Remote export: denied regardless of configuration. Local download: explicit selected confirmation; no server transfer; local copies persist. Infrastructure logging, real dispatch and production database remain unverified.
