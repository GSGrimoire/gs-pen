# PEN-030: extractor with responsive history/navigation rail

3 November 2026. Issue #38. This is a presentation and navigation change only, **not** a Site deployment or permission change.

## User request and exact interface behavior

The previous source UI had a left navigation rail, main extraction content and a third promo/recent-preview column, while mobile displayed the navigation block above the workspace. The owner asked for the extractor and menu/history **side by side** on desktop, and a mobile panel that overlays roughly three quarters of the width, closed by a `>` control or tapping outside.

- Desktop (viewport wider than 860 pixels): the original extraction workflow becomes the main **left** column. One unified **right** rail holds existing Extract, Recent, Create and Diagnostics navigation plus the latest eight loaded, owner-private extraction previews and a View all/Refresh history pathway. The redundant third/promo column is removed.
- Mobile/tablet (at most 860 pixels): the Extract workspace occupies full width. A Menu / History button opens the *same* rail as an approximately 75%-viewport-width right overlay with a backdrop. It closes via the arrow button, backdrop, Escape, or navigation; opening a saved history preview returns to Extract.
- No duplicate history API endpoint, data store, route or identity check. All previews are generated by existing `drawHistory`, backed by the existing owner-scoped history response. The full Recent view continues to provide filtering, paging, reopen and delete, with unchanged data path and deletion confirmation.
- Accessibility: labelled trigger, `aria-expanded`, mobile-only `role=dialog` / `aria-modal`, focus moved to close control on opening, keyboard Tab/Shift+Tab trapping, focus returned to opener on direct dismissal, main focus on navigation, scroll lock and reduced-motion support. The closed mobile rail is inert.
- No new provider fetches, model calls, telemetry payloads, stored user content, authentication, Site identity, database, retention, migrations, social publishing or GS Poster access are introduced.

## Review and tests

Files: `web/index.html`, `web/styles.css`, `web/app.mjs`, `e2e/test-lab.spec.mjs`, and this review. Existing nav browser fixtures are adapted to open the mobile drawer before interacting with navigation. New desktop/mobile assertions cover column placement, drawer width/edge, scrim click, arrow and Escape dismissal, focus cycle and restoration, navigation, no input loss, no page overflow, and reopening private saved history from the rail.

Synthetic tests and hosted build/lint/types must pass on the final feature head. This document is a **creator self-review**, not independent security or live Site verification. A future Site deployment must match the final reviewed source tree and pass owner/anonymous access checks under #27.
