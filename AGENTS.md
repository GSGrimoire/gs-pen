# GS Pen collaboration rules
Read docs/HANDOFF.md, BACKLOG.md and the relevant source before making changes. Treat source and passing tests as authoritative, not prior chat claims. One issue, branch and reviewed pull request per feature. Do not merge unreviewed code or publish unverified functionality. Never commit audio, transcripts, personal data, auth tokens or external-account cookies. Preserve the GS Scribe and GS VoiceStudio projects; no cross-project changes without explicit scope. For every change, run tests and record what was not verified. Keep interface errors truthful and distinguish URL recognition from authorized content retrieval.

Owner decision, 25 October 2026: apply the shared risk-based review policy across GS tools. Routine changes need a reviewable pull request, documented creator self-review and passing required checks; do not automatically invoke Claude. Allow one bounded correction attempt per found issue, then escalate an unresolved failure unless the owner authorizes further attempts. Changes to authentication/owner boundaries, private-data exposure, secrets, destructive migrations, publication security or shared critical infrastructure still require independent review before merge/deployment. Self-review is not independent verification. Reference: GSGrimoire/gs-tools-hub AGENTS.md, Risk-based review and escalation.
